01
Spherical Polygon Operations
Boolean set operations applied to geodesic polygons on a sphere. Edges follow great circles, so the shapes curve — intersection is computed in spherical coordinates, not projected space. The result differs from a planar computation whenever polygons span more than a few degrees.
Input polygon A or B (geodesic boundary)
Intersection result A∩B
Graticule (parallels & meridians)

Edges of spherical polygons are great-circle arcs, not straight lines. They appear curved when drawn on a 2D projection.

Set operations must be computed in spherical coordinates — applying planar intersection to projected coordinates introduces area errors that grow with polygon size and latitude.

Near the poles or antimeridian (180°), planar results can be completely wrong. GO.intersection handles these cases correctly.

02
Spherical Cap Spatial Index
A hierarchical spatial index on the sphere surface, where each node is a spherical cap — the set of all points within a given angular distance of a center point. Parent caps fully contain their children, enabling fast bounding-cap tests during traversal. Analogous to an R-tree but in spherical space.
Root / L1 — large bounding caps (dashed)
Leaf caps — tight around individual geometries
Indexed point geometries

A spherical cap is defined by a center point on the sphere and an angular radius θ. All points within great-circle distance θ of the center belong to the cap.

The containment test between a cap and a point is a single dot-product, making traversal extremely fast. Spherical cap trees are the spherical analogue of R-trees or BVHs.

03
Planar R-Tree (Spatial Index)
An R-tree organises geometries in a hierarchy of minimum bounding rectangles (MBRs). Each node's MBR contains all its children's MBRs. Spatial queries prune entire subtrees whose MBRs don't intersect the query region — reducing average complexity from O(n) to O(log n).
Root MBR — bounding box of all geometries
L1 nodes A, B — coarse spatial partition
L2 leaf nodes A1–B3 — tight MBRs around data
Individual geometries (points, polygons, lines)
Query window — only intersecting nodes traversed

For a range query, the tree is traversed top-down. Any node whose MBR doesn't intersect the query is pruned — its entire subtree is skipped.

Nodes A1 and A2 here are fully outside the query window; only A3 and part of B3 need checking. Instead of testing all 16 geometries, only 3–4 are candidates.

R-trees support insert, delete, range_query, and k_nearest_neighbors. Used in SpatialIndexing.jl and ArchGDAL.

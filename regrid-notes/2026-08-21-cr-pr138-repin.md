## API and assembly changes found

The source diff from the old pin to PR #138 changes CR's threaded sparse assembly in
`src/regridder/intersection_areas.jl`. It does not change the signatures of the DGG call
surface: `intersection_areas`, `get_all_candidate_pairs`, `assemble_sparse_matrix_coo`,
the intersection-operator traits/hooks, or the `Trees` interface remain compatible.

The implementation changes are:

- Threaded COO assembly now retains one triplet tuple per task in `_assemble_chunks`
  instead of concatenating all task vectors before CSC construction.
- Threaded `intersection_areas` routes those chunks through `_assemble_sparse` and a
  column-windowed `_sparse_from_chunks` path. It histograms coarse column blocks,
  buckets triplets into entry-balanced column windows, builds window CSC matrices in
  parallel with `sparse!`, and splices them into the final CSC.
- Small or serial assemblies retain the concatenation/ordinary `sparse` path.
- CR now validates equal row/column/value lengths for each COO chunk and preserves
  `sparse`'s duplicate-combination rules (`|` for `Bool`, `+` otherwise).
- Empty threaded COO results use `output_eltype(op, src_tree, dst_tree)` explicitly.

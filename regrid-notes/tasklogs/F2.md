T10's four API gaps that live outside `docs/`: the 8× eager gap against
`CR.Regridder` (gap 1), `missingval` from source metadata (gap 2), the
"which chunk holds this" accessor (gap 3), and recipe A surviving in
`README.md` and `examples/` (gap 5). Files touched:
`lib/GlobalRegridding/src/{conservative,rastergrid,spaces,api}.jl`,
`lib/GlobalRegridding/test/{runtests,test_conservative,test_executor,test_rastergrid}.jl`,
`src/regridding.jl`, `test/systems/crosssystem/{regrid,regrid_acceptance}.jl`,
`README.md`, `examples/{regridding,dimensionaldata}.jl`.

## Item 1 — the eager gap

| | 8 threads | 1 thread |
|---|---:|---:|
| `plan_regrid`, T10's build | **40.0 s** | 40.0 s (threads unused) |
| `plan_regrid`, now | **2.5 s** (2.49 / 2.53 / 3.22) | **15.5 s** |
| `CR.Regridder` | 4.2 s (4.18 / 4.19 / 4.29) | 20.4 s |

**16× at 8 threads and 2.6× at 1**, and the new path is now 1.7× faster than
`CR.Regridder` threaded and 1.3× faster serial — past the ≤1.5× target rather
than up to it. End to end, `DGG.regrid(dem; to = grid)` on the hydrology page
is **2.9 s against T10's 41.4 s**, and still answers 823 056 covered cells over
674.2192–3858.329 m, which is what T10 recorded.

### 1a — threading

`build_weights!(::Conservative, …)` now calls
`ConservativeRegridding.intersection_areas` with `True()` whenever
`Threads.nthreads() > 1`. Both halves of that call thread: the dual-tree descent
that finds candidate pairs and the clip that measures them. On this pair the
whole-domain block goes **15.42 s → 2.49 s (6.2×)**, and CR assembles `==` the
same matrix either way.

**Bit-identity is structural, not a coincidence.** `ChunkSplitters` partitions
the work items and the results are `vcat`ed in partition order, and the threaded
dual query concatenates its task results in spawn order — which is the order the
serial descent visits the same node pairs in. No pair is emitted twice, so
`sparse(rows, cols, vals, …)` has no duplicates to sum and is invariant to any
permutation of the triplets anyway. `_fillcoo!` then reads that matrix
column-major, so the denominators accumulate in the same order too.
`test_conservative.jl`'s "threaded and serial builds agree bit for bit" asserts
`colptr`, `rowval`, `nzval` and `denom` with `===` per element against `False()`
through the same operator and the same trees, on a 450 × 1152 pair with 2832
nonzeros.

**The empty pair, and why the guard is not a mask.** T3's blanket `False()` was
there because `multithreaded_dual_query` ends in `reduce(vcat, map(fetch,
tasks))` with no `init`, and `tasks` is empty exactly when the descent spawns
none — two chunks whose cells do not meet. A root-cap pre-check does **not**
decide this: caps bound their subtrees loosely, so two intersecting root caps
can still contain no intersecting cell pair, and the query still ends empty.
What is decidable after the fact is the reduction itself, so
`_intersectionareas` catches `ArgumentError` whose message contains
`"reducing over an empty collection"` and **rebuilds the pair serially**.

That classification is a routing hint and never a correctness argument. The
serial rebuild recomputes the block from the same two trees, so if the exception
was read wrongly the cost is one cheap recomputation and the answer is still the
answer; and if the threaded run failed for a genuine reason the serial run
raises it again. It is cheap because an empty reduction means no descent work
was done — `tasks` is empty. Measured on an empty pair: **0.020 ms** serial
against **0.465 ms** through the attempt-and-retry. The lib suite runs **30.4 s
at 8 threads against 30.5 s at 1**, so the retries the toy chunkings produce are
not visible at suite scale.

`test_conservative.jl`'s "a pair whose descent finds nothing" is the case, and it
asserts `!isleaf` of **both** roots first: a tree whose root is already a leaf
spawns one task unconditionally, and without that assertion the test passes
against a build that cannot survive an empty pair. (T3's original repro needed
40 cells for the same reason; the toy space's `ToyCapTree` is always a leaf and
hides it, so the two sides here are `RasterGrid`s.)

Threading is decided from `Threads.nthreads()` and carried in no state — a
single-threaded session takes the `False()` path with no `try` around it.

### 1b — the algorithmic half: `_rectcap`

Profiling the serial build (thread 1 only; with 8 threads and a serial build,
88 % of the samples are idle threads and swamp the ranking) put **56.86 % of the
whole build in `_rectcap`** — the node extent of a `RasterCellTree` — against
**1.75 % in `_rastercellcap`**, the per-cell cap F1 tabulated. The node extents
were the cost, not the cell caps.

The reason is the dual descent's shape. GeometryOps' `dual_depth_first_search`
carries a node's extent into the recursion and caches the *second* tree's child
extents (`_child_extents`, gated on `node_extent_is_expensive`), but the first
tree's children are re-derived once per visited node pair. `RasterCellTree` is
the first tree, and each of those derivations was a `_boxcap` with
`_BOX_CAP_SAMPLES = 3` — **sixteen chart evaluations and sixteen
`spherical_distance` calls per node per pair**.

`_boxcap` covers because the point of a box farthest from any centre is a
corner, so its extra samples buy a better *centre*, not a safer bound. Under
`LonLatToSphere` the centre through the four corners alone is already on the
box's mid-meridian, which is exactly where that monotonicity is exact — and a
box corner is a cell corner, so it is a pair of entries in F1's edge tables and
costs three multiplications. `_sampledcap` now takes that path, and `_rectcap`
is otherwise unchanged.

The gate is the box being under **180°** of longitude. Past that the corners
average toward the meridian *opposite* the box and the cap comes out small and
wrong (a 200°-wide equatorial box would get 80° when the truth is 180°); such a
box, and any chart with no `chartedgetables`, keeps the sixteen-sample
construction. A global raster's root and top nodes therefore keep it and every
deep node does not.

**Nothing about the weights moves**, and that is structural too: a cap only
prunes, both constructions cover, and only positive areas are stored — so every
pair with a real intersection survives either bound and the assembled matrix is
identical. Measured: **40.0 s → 15.5 s (2.58×), with the digest unchanged.**

The wide case does not pay for it. A/B'd in one session by `Core.eval`ing the
sixteen-sample method back in and out, on the shape that has wide nodes to
bound — the `regridding.jl` page's own global 360 × 180 lon/lat raster onto
HEALPix level 6, 268 154 nonzeros: **0.29 / 0.30 / 0.36 s** with the corner cap
against **0.46 / 0.51 / 0.47 s** with sixteen samples, `==` the same block. A
looser cap would have shown up as extra clipping here and did not.
`test_rastergrid.jl`'s existing coverage assertions (`tree_covers_dense`, the
densified ring containment for the banded, straddling and stripe rasters) still
hold — they densify every cell ring's great-circle edges and assert containment
in every node extent, which is what would catch an under-covering bound.

### What remains of the gap

Serial profile after, thread 1, 2098 samples at 5 ms, against `CR.Regridder`'s
own on the same pair (2672 samples). Inclusive, topmost occurrence:

| frame | ours before | ours now | CR |
|---|---:|---:|---:|
| dual descent (`get_all_candidate_pairs`) | 79.4 | 59.2 | 62.9 |
| ⤷ `node_extent` | 61.0 | 18.3 | 23.2 |
| ⤷⤷ `_rectcap` | **56.9** | **7.6** | — |
| ⤷ `child_indices_extents` | 4.6 | 10.4 | 11.3 |
| COO assembly | 13.6 | 34.8 | 25.8 |
| ⤷ `_intersection_sutherland_hodgman` | 4.4 | 11.2 | 7.4 |
| `cell_boundary` (IGEO7 destination) | 13.8 | 33.1 | 33.3 |
| ⤷ `snyder_inv_xyz` | 9.8 | 23.4 | 24.7 |
| `getcell` | 7.4 | 19.0 | 18.8 |
| `sparse` | 0.2 | 0.1 | 0.1 |

The two profiles are now the same shape, and the largest single frame on either
side is the **IGEO7 destination's own cell geometry** — `cell_boundary` through
`snyder_inv_xyz`, a third of the build, paid identically by both paths because
both descend the same `HierarchicalGridCursor`. Two things are left on the
table, neither in `lib/`:

1. **The DGGS cursor's node extents, 18.3 % − 7.6 % ≈ 11 % of the build.** The
   same recompute-per-pair pattern `_rectcap` had, on the destination side.
   `DGGSpace` already stores a cap per *chunk*; a cursor node inside a chunk
   derives its own. This is `src/systems`/`src/fallbacks` work.
2. **`snyder_inv_xyz`, 23 %.** IGEO7 cell boundaries. Shared with `CR.Regridder`
   exactly, so it is not a gap against it — but it is now the ceiling on this
   case, and a cached or vectorized inverse projection is the only thing that
   moves it.

The clip is 11.2 % against CR's 7.4 % on the same 2.26 M intersections, which is
the one place we do more per pair; both go through GeometryOps'
Sutherland–Hodgman with a `task_local_operator` cache, and the difference is the
source polygon each hands it — ours synthesized from edges, CR's read out of a
materialized corner matrix. Not worth materializing 810 000 polygons for: CR
allocates **11.9 GiB** to our **7.6 GiB** on this build.

**Not done, deliberately:** materializing per-chunk geometry on the eager path.
The measured answer no longer needs it — the eager build is already faster than
the materialized-mesh baseline it was 8× behind — so the O(1)-space construction
stays as designed.

## Item 2 — `missingval` from the source's own metadata

`Rasters.missingval(A)` is a **field accessor**, not metadata:
`DD.metadata(dem)` on a GDAL-backed `Raster` carries only `"filepath"`, and the
GeoTIFF's nodata has already become the `missingval` field by then (verified on
the hydrology DEM and on a WorldClim tile, whose `missingval` is `missing` and
whose metadata is likewise only `"filepath"`). The main package has **no Rasters
coupling at all** — it is not a dependency, not a weakdep, and appears only in
two `test/integration/` files — so the hook is what got built, per the brief's
own fallback.

`GlobalRegridding.sourcemissingval(data)` is the seam, `nothing` by default, and
it is now the **default of `missingval`** on `regrid`, `regrid!` and
`plan_regrid`. A `DimensionalData` array answers with the first of
`("missingval", "_FillValue", "missing_value")` its metadata carries, under a
`String` or a `Symbol` key — the CF spellings a NetCDF or GRIB reader does carry
through, so this is not a token route. An explicit `missingval =` still wins,
including `missingval = nothing` against a source that declares one.

Nothing was needed on the DGG side: `GR.plan_regrid(::DD.AbstractDimArray)` in
`src/regridding.jl` forwards `kwargs...` through `invoke`, so an unset
`missingval` picks up the new default. `test/systems/crosssystem/regrid.jl`'s
"a source's declared sentinel reaches the plan" is the assertion that the
forwarding does not swallow it — a sentinel-carrying field must give what the
same field with NaN gives, and `plan.missingval` must be the declared value.

**What remains for a Rasters extension**: one method,
`GlobalRegridding.sourcemissingval(A::Rasters.AbstractRaster) = Rasters.missingval(A)`.
It was not added here because it needs a `Rasters` weakdep on either this
package or `lib/GlobalRegridding`, and both resolve against a `Manifest.toml`
carrying three pinned repo revs; adding one is a resolution decision, not a
fixup. Until it lands, a GeoTIFF user whose nodata Rasters has *not* already
turned into `missing`/NaN still passes `missingval =` himself.

## Item 3 — `chunkat`

`chunkat(space, i)` is the chunk owning cell position `i`; `chunkat(space, p)`
is `cellat` composed with it, and is `nothing` exactly where `cellat` is. All
unexported.

| space | method | cost |
|---|---|---|
| any `RegridSpace` | `spaces.jl`, scans `cellindices` per chunk | O(ncells) |
| `RasterGrid` | `rastergrid.jl`, `cellsubscript` then one binary search per axis | O(log nchunks) |
| `DGGSpace` | `src/regridding.jl`, `searchsortedlast` over `space.starts` | O(log nchunks) |

`RasterGrid` also gained `chunkposition(space, cx, cy)`, `chunksubscript`'s
inverse, which the raster method needs and which had no spelling.

`test/systems/crosssystem/regrid_acceptance.jl` now names the south-pole chunk
with `chunkat` instead of T10's `findfirst` scan, and keeps the scan beside it
as the oracle — a wrong window would move the whole file onto a chunk that is
not the pole's, where every read assertion in it would still pass. The lib tests
assert the inverse law over every cell of every chunk on four chunkings
(including the transposed one, so a lattice slip cannot hide behind a symmetric
case) and that the disk-backed parent is still never read.

## Item 4 — law 2 outside `docs/`

Three files still taught recipe A: `README.md` built a corner mesh and called
`CR.Regridder` by hand, and both examples did the same at length. All three now
teach the `to =` / `from =` API, and the two examples were **executed** to
verify — not read.

**`README.md`** keeps the short form and its length. The `## Regridding` block
is now `DGG.regrid(temps; to = grid)`, the `to = cv` and `to = HEALPixSystem()`
spellings, the reverse direction through `to = GR.RasterGrid(dims)` with
`from = DGG.DGGSpace(grid)`, and the plan/apply pair — no `Regridder`, no
corner matrix, `import GlobalRegridding as GR` the only new import. The prose
under it says what a plan carries (method, both spaces, missing policy, hence
no keywords on apply), what `missingpolicy` means, and keeps the convexity
paragraph, which is still true and still points at
`regridding_conservation.jl`.

**`examples/regridding.jl`**, 256 → 288 lines. The destination is now
`GR.RasterGrid` over two `DD.Sampled` axes instead of a hand-rolled corner
matrix, sources are `DGG.DGGSpace(grid)`, and one `planfrom(grid)` helper
carries the whole recipe:

```julia
planfrom(grid) = DGG.plan_regrid(sample(grid); from = DGG.DGGSpace(grid),
    to = DST, missingpolicy = GR.Extensive())
```

`Extensive` on purpose: `Weighted` divides by the covered area and would answer
1 for `regrid(ones)` whatever the clipper did, which is exactly the failure the
file's last sweep exists to expose. Every number the old file asserted comes
back bit for bit — the file re-derives them from `plan.block.weights` rather
than from `CR.regrid!` — the field-error-shrinks-with-resolution law, the
three-systems-agree cross-check, and the conservation sweep in both directions,
which still asserts where the law holds (`Authalic(IGeo7System) 3` at 9.19e-15
conservative, 1.85e-14 conservative-onto) and still *prints* the shortfalls
where it does not (HEALPix 4 → 1.994, A5 4 → 0.0188, ISEA4R 4 → 47.996). No
tolerance moved.

**`examples/dimensionaldata.jl`**, 246 → 242 lines. The zonal-mean section's
hand-built regridder collapses to one call —
`DGG.regrid(elevation; to = DST, from = DGG.DGGSpace(DGG.PartialGrid(lk)),
missingpolicy = GR.Weighted(0))` — matching the old result to **4.6e-13**.

Both run green under the root project at 8 threads: `ALL CHECKS PASSED`,
`FAILURES = 0`.

### A bug the examples found: `AuthalicSystem` as a regrid target

`DGG.DGGSpace(levelgrid(AuthalicSystem(IGeo7System()), 3))` threw
`MethodError: no method matching ncells(::AuthalicSystem{IGeo7System, Float64},
::Int64)`. `AuthalicSystem` answers the level-grid contract with a grid type of
its own (`AuthalicGrid`) and is therefore not required to implement
`ncells(sys, l)` — the escape hatch `AbstractGrid` documents, and the one
shipped system that takes it. `src/regridding.jl` asked the *system* for a
complete level's size in three places, so it broke on exactly that system.

Fixed with one helper that asks the level grid instead, `O(1)` because
`levelgrid` is:

```julia
_levelcells(sys::AbstractHierarchicalGridSystem, l::Integer) = ncells(levelgrid(sys, l))
```

used in `_chunklevel` (sizing a chunk level), `_chunkwindows` (deciding a level
is complete) and `arealevel` (matching a level by mean cell area). The last of
those means `regrid(A; to = AuthalicSystem(...))` — level chosen by area — was
broken and untested too. `test/systems/crosssystem/regrid.jl`'s "the space
contract" now builds an authalic `DGGSpace`, asserts its chunks partition the
cells, and asserts `arealevel(auth, SRC) == arealevel(IGeo7System(), SRC)`
(the authalic wrap does not change cell counts, so it must not change the
matched level).

## Seams for the export review

New unexported names, all reachable as `GlobalRegridding.x`:

- **`chunkat`** — the counterpart of `cellindices`, and the one a caller reading
  one destination chunk needs. Worth exporting alongside `cellindices` and
  `cellat`, which are exported; a space overrides it the same way it overrides
  `subtree`.
- **`sourcemissingval`** — the extension point a reader defines a method on. It
  has to be reachable to be extended, so it is an export candidate on the same
  footing as `knownempty` (T8's list).
- `chunkposition` (`RasterGrid`), beside the exported-by-nobody
  `chunksubscript`/`chunkbox` family.
- `MISSINGVAL_KEYS`, the metadata keys consulted. Documentation, not API.

Private, named here only so a reader of the diff can find them:
`_intersectionareas` and `_isemptyreduction` (`conservative.jl`), `_sampledcap`,
`_boxcorners` and `_chunkofindex` (`rastergrid.jl`), `_levelcells`
(`src/regridding.jl`).

Still open from T8/T10: `knownempty`, `isvalidvalue`, `residency`, `LazyStats`,
`weightbudget`, `databudget`, `spilledfiles`, `usesreference`, and T9's question
about re-exporting the method and policy names from `DiscreteGlobalGrids`.

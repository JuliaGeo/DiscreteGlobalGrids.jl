## Acceptance law 1 — the south-pole case

A `DEMTiles <: AbstractDiskArray` synthesizes each block it is asked for from an
analytic terrain function and records the request; everything below sea level is
nodata, so the ocean patches are irregular and reach into the polar band. The
source is **3600 × 1800 in 300² tiles** (12 × 6 of them), Float32.

`to = IGeo7System()` area-matches to **level 7** — 8 235 432 destination cells,
chunked at ancestor level 3 into **3432 chunks** of 2401 cells. The chunk
holding the south pole spans latitudes −89.99 to −85.88 and is met by the whole
southernmost tile row.

| assertion | the mutant it kills |
|---|---|
| planning reads nothing; `residency(A).loads == 0` after construction | a plan that touches data — L1, and the reason planning an 8-million-cell destination costs milliseconds |
| every read is `(_, 1501:1800)` and there are 12 of them | discovery that over-connects (tiles from the row above) or under-connects (a cap that does not cover the pole, a missing dilation); either is invisible in the result's shape |
| streamed ≡ held, `isequal` | streaming that drops or double-counts a chunk pair |
| `streamstats.peakbytes ≤ 2 × tile`, `heldstats.peakbytes ≥ 8 × tile` | `budget` ignored — everything held, or nothing ever loaded |
| streamed ≈ eager on a cropped extent, NaN pattern equal | per-chunk-pair accumulation that does not sum to the whole-domain block; `Weighted`'s blanking applied per pair rather than at finalize |
| `0 < count(isnan, held) < length ÷ 2` | a source whose nodata never reaches the destination — without it the comparison above is vacuous |
| 12 spill files, and a second read off disk gives the same values | a `Spilled` block that deserializes wrong, or is silently rebuilt (the second read takes 0.05 s against 2.4 s for the first, so the files are what answered) |
| sentinel + `missingval` ≡ NaN run, **and** sentinel without `missingval` differs | `missingval` consulted only on the eager path, or ignored — the second half is what makes the first non-vacuous |

Measured, on the streamed run: peak resident source **360 000 B** — exactly one
tile — against **4 320 000 B** held, twelve tiles, same 12 loads and the same
answer.

The brief's 7200 × 3600 / 600² was measured first: it area-matches to level 8
(57 648 012 cells, 24 012 chunks), reads the same 12-tile polar row, holds
17 280 000 B, and costs **6.7 s per polar-chunk read** — the file builds weights
six times, so about 40 s of clipping alone. Shrinking 4× keeps every structure
identical (12 connected tiles, one fan-in chunk, the same nodata geometry) and
brings the file to 19 s.

## API gaps, for the orchestrator

1. **The eager whole-domain path is 8× slower than the `CR.Regridder` recipe it
   replaces**, and the two halves of that are separable. On hydrology's DEM
   (810 000 source cells → 823 543 IGEO7 cells, 2 259 258 nonzeros), all four
   runs giving the same answers:

   | | 8 threads | 1 thread |
   |---|---|---|
   | `plan_regrid` (+ apply) | **40.9 s** (+0.5) | **40.7 s** |
   | `CR.Regridder` (+ two `regrid!`) | **5.0 s** (+0.1) | **20.9 s** |

   - **The new path does not use threads at all** — 40.7 against 40.9 — so it
     leaves 7 of 8 cores idle where CR's dual search gets 4.2×. Design §5's
     `threaded = False()` is a workaround for a chunk pair with **no**
     intersections crashing CR's `reduce(vcat, ...)`, and a `DirectPlan`'s
     single whole-domain pair cannot be empty. Making the guard conditional on
     the pair rather than blanket is the fix.
   - **A residual ~2× remains single-threaded** (40.7 against 20.9) that
     threading does not explain: it is `RasterGrid`'s cell tree against CR's
     `TopDownQuadtreeCursor`, the COO fill, or `sparse()` assembly — P1's split,
     now at 2.3 million nonzeros.

   Both are in `lib/`, so neither is mine. Together they are the single biggest
   number in the docs build: hydrology's page went from ~5 s to 41 s.
2. **`missingval` is still not wired from Rasters metadata** (T9's deferral).
   The hydrology page works only because `Rasters` has already turned the
   GeoTIFF's nodata into `missing`/NaN by the time `regrid` sees it; a user
   handing `regrid` a sentinel-carrying array must pass `missingval =` himself,
   and nothing says so.
3. **No accessor for "which chunk holds this cell".** The acceptance file finds
   the south pole's chunk with
   `findfirst(c -> p in cellindices(space, c), 1:nchunks(space))`. `DGGSpace`
   already stores `starts`, so `chunkat(space, position)` is one
   `searchsortedlast`; without it, anything that wants to read one destination
   chunk either scans or reaches into the struct.
4. **Method and policy names are still not re-exported from DGG.** The docs now
   carry the same `import GlobalRegridding` the tests do. T9's one-line question
   is still open, and the answer decides whether `docs/Project.toml` keeps the
   dep.
5. **Recipe A survives outside `docs/src/tutorials/`**, which is not mine to
   change: `README.md:155-172` still teaches `CR.Regridder(manifold, dst, src)`
   as the regridding interface, and `examples/regridding.jl` /
   `examples/dimensionaldata.jl` still build point matrices by hand
   (recipe B of `regrid-notes/current-regrid-ux.md`). Law 2 is not finished
   until those move.

## P2 pointers

Reproduce the acceptance setup:

    cd <worktree>
    julia --project=test -e 'using Test; using DiscreteGlobalGrids;
        include("test/systems/crosssystem/regrid_acceptance.jl")'

Everything is addressable afterwards through the module:

    T = Main.RegridAcceptanceTests
    T.DEM            # the tiled disk raster; T.reads(T.DEM), T.resetreads!(T.DEM)
    T.DST            # the DGGSpace, level 7, 3432 chunks
    T.POLARCELLS     # 8093774:8096174 — the fan-in destination chunk
    T.polarchunk(T.DEM; budget = 2^20)   # -> (values, LazyStats), streaming
    T.polarchunk(T.DEM; budget = 2^30)   # -> (values, LazyStats), holding
    T.eagerreference()                   # the same cells off a cropped source

The knobs worth sweeping: `NX`/`NY`/`CHUNK` (7200/3600/600 is the full-size
case, 6.7 s per read), `budget` (the hold/stream switch is
`databudget(budget) < 12 × CHUNKBYTES`), and `storage = Spilled(dir; maxbytes)`
(`maxbytes = 1` forces every block through the filesystem).

For the allocation profile at a tiny budget, `T.polarchunk(T.DEM; budget = 2^20)`
is the loop to profile: 12 loads, one 360 000-byte scratch, no held chunks. For
the `Sys.maxrss()` delta across a full south-pole read, note that `residency`
already reports the exact figure and disagrees with `maxrss` only by the weight
blocks, which `nblocks(plan.storage)` counts separately.

The 8× finding in gap 1 above is the first thing to `judge` against P1's
baselines: P1 measured the conservative plan-build split (clipping vs COO fill
vs `sparse()` assembly) on a toy, and this is the same split at 2.3 million
nonzeros with the answer already known to be construction-bound.

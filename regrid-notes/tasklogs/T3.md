## What `build_weights!(coo, Conservative(), …)` guarantees

- Entry `(j, k)` is the spherical area of the overlap of destination cell
  `dst_inds[j]` with source cell `src_inds[k]`, on the manifold both spaces
  report. Both sides must report the same manifold; a mismatch throws.
- `denom[j]` accumulates exactly the same areas, so one block's denominator is
  the part of destination `j` that *this* source chunk covers, and blocks over
  one destination chunk sum to its covered area.
- A conservative block **always** carries a denominator, including when the two
  chunks do not meet: `adddenom!` is called once with `0.0` before anything can
  return early, so zero coverage never degrades into "no denominator, finalize
  as a raw sum".
- The partition invariant holds by construction — the descent runs over trees
  restricted to the two chunks, so no pair outside `src_inds` is ever visited.
- No package-level state. Every intermediate is local to the call, and the only
  mutable object (the clipping cache) comes from CR's `task_local_operator`, so
  concurrent builds of different chunk pairs are independent.
- Empty `dst_inds` or `src_inds` return an untouched/denominator-only `coo`.

## Load-bearing CR entry points

All `@public`; nothing internal is copied or patched.

| entry point | role |
|---|---|
| `intersection_areas(manifold, threaded, dst_tree, src_tree; intersection_operator)` | the dual-tree descent + assembly driver |
| `DefaultIntersectionOperator(manifold)` | the actual clip + area, unchanged |
| `IntersectionReturnStyle` → `InPlace()` | lets the operator push its own COO triplets |
| `output_matrix_size(op, src_tree, dst_tree)` | **memory**, not correctness: without it the block matrix is sized by whole-space cell counts, so every block would allocate a `colptr` of `ncells(src_space)+1` |
| `task_local_operator(op)` | forwarded to `inner`, so each assembly task gets its own `SutherlandHodgmanCache` |

`Trees.getcell(tree, i)` is how cells are read, so the `subtree` contract is
"leaf indices and `getcell` indices are cell positions of the space" — the same
convention `celltree` uses.

**Deviation:** `Trees.IndexLocalizerRewrapperTree` is *not* used. It is neither
exported nor `@public` (the `Trees.jl` comment lists it as private), and its
semantics are the reverse of what is needed here — it forwards
`child_indices_extents` unchanged and only shifts `getcell` by a constant, so it
cannot relabel a chunk's global cell positions to `1:length(inds)`. Localization
therefore happens in a `BlockAreaOperator` through the documented operator seam,
which has the further advantage of working against *any* tree a space supplies,
including ones this package cannot wrap.

**Upstream bug found (CR):** `intersection_areas` with `threaded = True()`
**errors on a chunk pair whose cells do not meet** —
`MultithreadedDualDepthFirstSearch.multithreaded_dual_query` ends in
`reduce(vcat, map(fetch, tasks))` with no `init`, and `tasks` is empty when no
child pair satisfies the predicate. Reproduced with two disjoint toy spaces
(40 cells each, 4 threads). Blocks are therefore built with `False()`; the
executor's parallelism is over chunk pairs. Fix upstream is a one-word `init`.

## The `subtree` seam

    subtree(space::RegridSpace, inds) -> tree

Unexported, defined in `conservative.jl`. Two paths:

1. `inds` covers `1:ncells(space)` ⇒ returns `celltree(space)` untouched. The
   whole-domain `DirectPlan` therefore builds no tree at all.
2. otherwise ⇒ `CellCapTree(space, inds)`, a balanced bounding-cap BVH (leaf
   size 16) over `inds` **in the order given**, one cap per cell derived from
   `getcell`.

The fallback needs only `getcell` + `manifold` from a space — not `celltree`,
not `cellat`, not `cellcentroid` — so any space works out of the box. What it
costs: one polygon construction per cell per block build, and it assumes the
space's cell order carries spatial locality.

**RasterGrid (T2) and the DGG spaces (T9) should define their own method**
returning a restricted view of their real tree: same index convention (cell
positions, not chunk-local), `SphericalCap` node extents, `Trees.getcell` and
`Trees.ncells` defined. A raster chunk is a rectangle of the lattice, so its
subtree should be O(1) to construct rather than O(chunk).

## `@test_broken`: non-convex destination cells

`test_conservative.jl` defines a one-cell `DensifiedCellSpace` whose ring is a
graticule box with its parallel edges sampled — non-convex, because a
great-circle chord between two points of a parallel bows poleward of it. Against
a 16×8 tiling of the sphere:

- as **source** (the clipped subject): total intersection area = the cell's own
  area to machine precision. Passes.
- as **destination** (the clip ring): **0.5975 measured against 1.1115
  expected — 46 % of the mass lost**. `@test_broken`, naming the GeometryOps
  Sutherland–Hodgman non-convex-clip fix
  (`GeometryOps/src/methods/clipping/sutherland_hodgman.jl`).

This is the same defect that makes conservative regridding *onto* densified
DGGS cells wrong, isolated to ~30 lines and reproducible without any DGGS. When
the GO fix lands, flip it to `@test`.

The toy's own cells are all convex, so the antimeridian case is *not* broken:
a 2×2 space over lon `(135, 225)` regrids onto the global 8×4 space as an exact
4-entry permutation. Nothing wraps longitude — the geometry is unit-sphere
points — and that test says so.

## Performance (plan-construction hot path)

Single thread, M-series, toy lon–lat spaces, destination 2× refined:

| dst cells | src cells | nonzeros | BVH subtree | toy flat `celltree` |
|---|---|---|---|---|
| 2048 | 512 | 2944 | 25.7 ms | 21.3 ms |
| 8192 | 2048 | 12032 | 94.9 ms | 215.9 ms |

Both paths find the identical candidate set (equal nonzero counts), so the
difference is descent quality alone: the flat tree is quadratic in cell count,
the BVH is not, and it overtakes by ~2.3× at 8k cells and widens. Cost is
~8 µs per emitted nonzero and is **dominated by the spherical clip**, not by
the descent, the relabelling, or the sparse assembly — which is why the
intermediate `SparseMatrixCSC` (built by `intersection_areas`, then `findnz`'d
into the COO) was left in place rather than short-circuited: it is noise against
the geometry, and it keeps the code correct if intra-block threading is ever
turned back on.

Implication for P1: the lever is fewer candidate pairs (good `subtree`
implementations) and a faster clip, not this file's bookkeeping.

## Seam the orchestrator must close

`test/runtests.jl:83` (T1's "unimplemented hooks" testset) asserts

    @test_throws "Conservative" build_weights!(WeightCOO(…), Conservative(), space, inds, space, inds)

which is exactly what T3 implements. It now fails with "No exception thrown".
T3 does not own `runtests.jl`. T4 has implemented `NearestCell` and
`BilinearPoint` too, so no shipped method is left unimplemented — the assertion
should be deleted, or retargeted at a locally-defined method with no
`build_weights!` method.

# T4 — NearestCell + BilinearPoint weights

Files: `src/interpolation.jl`, `test/test_interpolation.jl`. 32 assertions,
`Pkg.test()` green. Nothing stubbed.

Real: `build_weights!` for `NearestCell()` and `BilinearPoint()`, the chart
accessor the bilinear stencil is written against, and
`support_radius(::BilinearPoint, space)`.

## The chart accessor — exactly what a charted space must implement

Five unexported generic functions in `GlobalRegridding`, all dispatching on the
space. `hascellchart(space) = true` is the gate; each fallback throws an
`ArgumentError` naming the missing method.

| method | returns |
|---|---|
| `chartaxes(space)` | `(xs, ys)`: strictly monotonic vectors of cell-**centre** coordinates in the space's native units. Either direction (a north-to-south lat vector is passed as is — the locator flips it and maps indices back). Lengths are the lattice size; cell `(ix, iy)` is centred at `(xs[ix], ys[iy])`. Called once per block, so materializing is fine. |
| `chartcoords(space, p)` | `(x, y)` for a `UnitSphericalPoint`, in the same coordinates as `chartaxes`, or `nothing` when `p` is not on the chart (that destination emits nothing). A non-periodic axis must be answered on the branch its axis vector is written on. |
| `chartposition(space, ix::Int, iy::Int)` | the cell position of lattice cell `(ix, iy)` — the inverse of the subscripting `chartaxes` implies. Only ever called in range. |
| `chartperiod(space)` | `(px, py)`, the period of each axis in native units or `nothing`. **Defaults to `(nothing, nothing)`**; `360.0` for a degree-longitude axis that closes. Must exceed the span of that axis's centres. |
| `chartspacing(space)` | `(Δx, Δy)`, an upper bound in **radians of arc** on the distance between lattice-adjacent cell centres. Its only consumer is `support_radius`. |

Assumption: **separable** axes — rectilinear, irregular spacing allowed,
curvilinear not. An axis of length 1 degrades to nearest-neighbour.

`RasterGrid` (integration wave) maps onto this directly: centres from the edge
vectors in lookup order; `chartposition` = the same `(ix, iy) → position`
flattening `cellindices`/`getcell` use; `chartcoords` = the inverse of the
`native → UnitSphericalPoint` transform; `chartperiod = (360.0, nothing)` only
when the longitude edges close the globe; `chartspacing` from the largest edge
step. Until those five exist, `BilinearPoint` on a `RasterGrid` source throws
`chartaxes(::RasterGrid) is not defined`.

## No-denominator finalize semantics (executor must honour)

Neither method calls `adddenom!`; their blocks carry `denom === nothing`. Both
sample a point — there is no covered area to divide by.

- `denom === nothing` means **raw weighted sum**, never "zero coverage". A
  finalize that blanks such a destination blanks every point-sampled cell.
- Stencil weights sum to `1` per destination once accumulated over all source
  chunks, so under `Extensive` the result is the sampled value. Under
  `Weighted`, dividing by the accumulated *valid* weight gives the same answer
  where the stencil is clean and a renormalized stencil where part of it was
  missing — also correct. `Weighted`'s threshold has no block denominator to
  test against here; test valid weight against total accumulated weight, or
  skip.
- A destination row empty in *every* block is a genuine miss (centroid outside
  the source's coverage, or unchartable) and is the missing policy's problem.

## Boundary and wrap

- Interior: 4 points, product weights, sum `1`.
- Past the outermost centre on one axis (the outer half-cell and beyond):
  nearest on that axis, linear on the other — 2 points. Past both: 1 point,
  weight `1`. It never extrapolates.
- Periodic axis: there is no outside. The coordinate is reduced by `mod` into
  `[xs[1], xs[1] + p)` and the seam between `xs[end]` and `xs[1] + p` is an
  interval like any other, so a global lon grid has no discontinuity at ±180.
- Exactly on a centre: one point on that axis; zero weights are never emitted.

## Partition invariant

Both builders emit only entries whose source cell lies in `src_inds` —
`NearestCell` drops a hit owned by another chunk, `BilinearPoint` emits its own
share of a straddling stencil. Tested: the union of the two chunk blocks equals
the unchunked stencil, no key outside its own chunk, row sums still `1`.
Membership is O(1): arithmetic for an `AbstractUnitRange`, otherwise one `Dict`
per block.

## Deviations

1. `support_radius(::BilinearPoint, src)` is `max(chartspacing(src))` — a full
   centre spacing, not the tasks doc's half a cell. It is an upper bound; over-
   reporting only costs discovery work, under-reporting silently truncates
   stencils.
2. That call **throws** for a chartless source rather than returning `0.0`, the
   same error `build_weights!` would throw. Discovery must not probe
   `support_radius` for methods it will not run.
3. `test/test_interpolation.jl` implements the five chart methods for
   `ToyLonLatSpace` (`toyspaces.jl` is frozen) and defines two empty
   `RegridSpace` subtypes for the gate tests. Test files share `Main`, so every
   helper there is prefixed `t4_`.

## Seams

- The chart accessor is **unexported** (module file frozen) and absent from the
  module docstring's layout list. An outside space implements it as
  `GlobalRegridding.chartaxes(...)` etc. Consider exporting it, or re-homing it
  with the space contract, in a later wave.
- Design §7 question 2 (a bilinear chart for non-raster sources) stays open:
  the accessor as specified is separable-lattice only, so DGGS sources remain
  gated off by `hascellchart`.
- `NearestCell` requires `cellat` of the source and `cellcentroid` of the
  destination, checked by `hasmethod` and reported as `ArgumentError`s rather
  than `MethodError`s.

## Finalize semantics — denom × policy

Accumulators, all length `ndst`, all `Vector{Float64}`:

| name | meaning |
|---|---|
| `num` | `Σₖ W[j,k]·src[k]`, invalid `src` entries contributing 0 |
| `cover` | `Σₖ W[j,k]·valid[k]` — the weight of the sources that were *not* missing |
| `total` | accumulated **reference**: the block's `denom` if it has one, else its row sums `W·1` |

| block | `Extensive()` | `Weighted(t)` |
|---|---|---|
| **with** a denominator | `num` | `num / cover`, blanked where `cover ≤ 0` or `cover < t·total` |
| **without** one | `num` | `num`, blanked where `cover ≤ 0` or `cover < t·total` |

The decision, and its rationale: **a method's denominator is its declaration of
what full coverage weighs, and only a block that declares one is normalized.**
Weights that already sum to one (`NearestCell`, `BilinearPoint`) are returned as
built rather than silently renormalized over whatever part of the stencil
survived; a truncated stencil is *blanked*, not rescaled. A point method that
prefers rescaling opts in by calling `adddenom!` with its stencil weight and
lands in the first row — **T4's seam, one line, no executor change.**

Notes T6 will care about:

- `Weighted` is invariant to source NaN padding in the sense the divisor is
  `cover` (valid weight), never the total weight — a destination fed only by
  valid sources is bit-identical whether or not NaNs exist elsewhere. A
  destination that *does* lose part of its coverage to padding is blanked once
  the valid fraction drops below `t`; that is `Weighted`'s job, not a violation.
- `t = 0` means "any valid source at all" (the `cover ≤ 0` clause carries it), so
  `Weighted(0)` never divides by zero.
- `Extensive` blanks nothing. A destination no valid source reached is a raw sum
  of `0.0` — the lost mass, not an absence of one.
- Blank sentinel: `missing` when `eltype(out)` admits it, NaN otherwise
  (`_maskedvalue`). Output element type is
  `float(nonmissingtype(eltype(data)))`, re-unioned with `Missing` exactly when
  the source carries it — so an `Int` source regrids to `Float64` and can still
  be blanked.

## What T7 calls, per chunk pair

All unexported, all in `executor.jl`, all allocation-free (verified `@allocated
== 0` on the second call, kernels type-stable under `@code_warntype`):

    blockreference!(ref, block) -> ref      # ref .= denom, or row sums; data-independent
    addreference!(ref, block)   -> ref      # accumulating form — use this across the
                                            # source chunks of one destination chunk
    applyblock!(num, cover, block, src, valid = nothing, ref = nothing)
    finalize!(out, num, cover, total, policy, hasdenom::Bool)
    finalize!(out, num, cover, total, block::WeightBlock, policy)   # reads hasdenom off the block

Contracts:

- `applyblock!` accumulates into `num` and `cover`; it never zeroes them. Reset
  once per destination chunk per slice, accumulate over every connected source
  chunk, then `finalize!` **once**.
- `src` is one source chunk's cells flattened in `cellindices` order;
  `length(src) == size(block, 2)` is checked.
- `valid === nothing` asserts every entry of `src` is valid and takes the
  shortcut of crediting the block's reference into `cover` instead of a second
  matvec. Otherwise `valid` is any vector of `length(src)` read entrywise:
  `missing`/NaN ⇒ 0, `Bool` ⇒ itself, anything else ⇒ 1. **Passing `src` itself
  is the intended call** — it derives the mask from the data with no mask array.
  The eager path uses `anyinvalid(x) ? x : nothing`; `anyinvalid` is free for
  element types that cannot hold an invalid.
- `ref` is that block's own reference vector, used only on the
  `valid === nothing` path, and only to avoid recomputing row sums per slice.
  Pass it if you cache it beside the block; `nothing` recomputes.
- `total` for `finalize!` is the *accumulated* reference over the same set of
  blocks (`addreference!` per block). In the whole-domain case there is one
  block, so `total === ref`.
- `hasdenom` is a per-plan property (one method ⇒ all its blocks agree).

Also there: `applyplan!(out, plan::DirectPlan, src)` — the whole-domain slice
loop, `ndst × nslices` out of `nsrc × nslices`. One set of accumulators and one
reference vector for all slices (law L4's eager form).

## `cellarea` seam

`cellarea(space::RegridSpace, i) = GO.area(manifold(space), getcell(space, i))`
in `executor.jl`, unexported, overridable by a space with a closed-form area.

**Nothing in the executor calls it.** A destination's coverage threshold is
measured against the denominator its method reported, not against the
destination cell's own area — which is what the frozen `Weighted` docstring
already promises ("as a fraction of the block's denominator") and what keeps
finalize free of polygon construction. It exists for methods and callers that
want an area the contract does not otherwise expose. If T3 also defines a
`cellarea`, the two are the same function and `executor.jl` includes last.

## Flattening and N-D

- `spatialdims(A)` (unexported): a `DimArray` answers with the positions of its
  `XDim`/`YDim` dims; anything else answers `(1, 2)`, or `(1,)` for a vector.
- `resolvespatialdims(data, nsrc)` checks that answer against
  `ncells(src_space)` and falls back to the other reading before throwing a
  `DimensionMismatch` — so a `(cells, time)` source resolves without a trait
  override.
- Spatial dims must be **leading and contiguous**; otherwise an `ArgumentError`
  says to `permutedims`. The source is then one `reshape(parent(data), nsrc,
  nslices)` and each slice is a contiguous column view — no per-slice copy.
- Convention: `vec` over the spatial dims in memory order, which must be the
  order the space numbers cells in. Verified to agree with `ToyLonLatSpace`
  (longitude fastest) and with T2's `RasterGrid`.
- Output: `(ndst, other dims...)`, non-spatial dims passed through 1:1. A
  `DimArray` in yields a `DimArray` out with dims
  `(DD.Dim{:Cell}(1:ndst), otherdims...)` — a plain axis, for DGG to replace in
  T9. A plain array in yields a plain array out.

## API additions and deviations

1. **`from = nothing` kwarg** on `regrid`/`regrid!`/`plan_regrid` — **for
   review**. Not in the design. `from::RegridSpace` uses that space; `nothing`
   calls `RasterGrid(data)`. Needed because at this layer the source space has
   to come from somewhere and DGG's sugar (T9) is not here yet. If the design
   would rather resolve the source from `to`'s package, this is the kwarg to
   delete.
2. `plan_regrid` errors on `lazy = true` ("implemented in T7"); `regrid`/
   `regrid!` on a non-`DirectPlan` likewise.
3. `chunks` and `budget` are validated (positive sizes, positive budget,
   `GridChunks`/tuple/`nothing`) and then ignored, documented as lazy-path knobs.
4. `to`/`from` must be `RegridSpace`s here; anything else is an `ArgumentError`
   naming the type and pointing at the space-supplying package.
5. `plan_regrid` requires `manifold(dst) == manifold(src)` — a mismatch is an
   error, never a silent reprojection.
6. `wholeblock(method, dst, src)` (unexported, `api.jl`) is the one
   `build_weights!` call over `1:ncells` on both sides.

**T6 correction (finalize semantics).** The denom × policy table above no longer
holds for `Weighted`: it now divides by `cover` for **every** block, denominator
or not. The carve-out contradicted `Weighted`'s own frozen docstring ("divided by
the accumulated weight of the source cells that were not missing") and broke
acceptance law 3 for the point methods — a bilinear stencil that lost one of four
points to a NaN returned 0.75× the value of a constant field instead of the
value. `threshold`, not the block, decides whether a truncated support is kept.
Clean supports are unaffected (`cover == 1`), so only `Extensive` now differs
from `Weighted` for a no-denominator block. `finalize!`'s `hasdenom` argument is
retained but selects nothing. `test_executor.jl`'s "block without a denominator"
testset was updated to match.

## `ChunkedPlan`

    ChunkedPlan(method, missingpolicy, dst_space, src_space, storage, budget, chunks)
    ChunkedPlan(method, missingpolicy, dst_space, src_space;
                storage = PerChunk(), budget = 2^30, chunks = nothing)

Seven fields — the design's field set plus `chunks`, the output chunking, which
is a `GridChunks`, a tuple of chunk sizes, or `nothing` to derive. `budget` is
stored and **not yet consulted**: T8's knob, validated by `api.jl` already.

- `blockfor(plan, dstchunk, srcchunk) -> CachedBlock` — the storage seam.
- `buildblock(plan, dstchunk, srcchunk) -> WeightBlock` — one `build_weights!`
  call over `cellindices` of both chunks. Geometry only, so a rebuild after
  eviction costs exactly what the first build cost.

## `PerChunk` — keying, LRU, thread-safety

Key is `(dstchunk::Int, srcchunk::Int)`. Value is a `CachedBlock`: the block, its
`blockreference!` vector (data-independent, so computed once and reused across
every slice and every read), and its approximate byte size.

- `PerChunk(capacity)` / `PerChunk(; capacity, maxbytes)`, both defaulting to
  `typemax(Int)`. Either bound evicts; **the entry just touched is never
  evicted**, so `capacity = 1` still works.
- LRU is a monotone clock stamp plus a linear scan for the minimum on eviction —
  O(resident) per eviction, which is bounded by `capacity` and is noise against
  a weight build. No new dependency.
- Bytes are computed from the sparse arrays (`16·nnz + 8·(ncols+1)`, plus denom
  and ref), never `summarysize`.
- **Concurrency**: one `ReentrantLock` around the dict, *never held across a
  build*. `getblock!` = locked lookup-and-touch → build outside the lock →
  locked insert, keeping whichever entry got there first. Two tasks racing one
  key may both build; the loser's block is dropped. Different keys never
  contend beyond the dict. Verified: four tasks reading four destination chunks
  of one plan, and eight tasks racing one destination chunk, both give the eager
  answer.
- `nblocks(storage)`, `storagebytes(storage)` — unexported accessors for tests
  and for T8's budget accounting.

## Discovery contract

    connectedchunks(dst_space, dstchunk, src_space; radius = 0.0) -> Vector{Int}
    connectedchunks!(out, dstcap::Cap, src_space; radius)   # reuses `out`
    connectedchunks!(out, dstcap::Cap, srctree;   radius)   # tree already in hand
    connectedchunkpairs(f, dst_space, src_space; radius)    # batched dual descent
    chunkextents(space) -> Vector{Cap}    # indexed by chunk number
    chunkextent(space, chunk) -> Cap      # generic: walks the chunk tree

Ascending, deduplicated. **A superset, never a subset** — an extra pair costs one
empty block, a missing pair is silent data loss.

- The descent is `STI.dual_depth_first_search` with the destination side wrapped
  as `CapQuery`, a one-leaf tree. A hierarchical *source* chunk tree therefore
  prunes level by level; a flat one degenerates to the pairwise cap scan, which
  is all a flat tree can offer. `connectedchunkpairs` is the both-hierarchical
  form for T9.
- Dilation is in the **predicate**, not in a rebuilt cap:
  `DilatedIntersects(r)(a, b) = spherical_distance(a.point, b.point) <=
  a.radius + b.radius + r`. Valid at every level (a node's dilated cap contains
  its children's dilated caps), and it clamps nothing because it never
  constructs a radius > π.
- `radius` comes from `support_radius(method, src_space)`, read once at
  `LazyRegridArray` construction. Note T4's warning: `support_radius` *throws*
  for `BilinearPoint` over a chartless source, so construction is where that
  error now surfaces.

## `readblock!` — the algorithm and its residency profile

`LazyRegridArray{T,N,NS,A,P,K,C} <: DiskArrays.AbstractDiskArray`, dims
`(destination cells, source's non-spatial dims...)`. `haschunks` is `Chunked()`;
`eachchunk` is the destination's own chunks on the cell axis (when they are
contiguous ascending runs, else one whole chunk) × the source's chunking of the
pass-through dims.

Per `readblock!(A, aout, cellrange, otherranges...)`:

1. `_coveringchunks` — destination chunks whose cell-position span meets
   `cellrange` (spans precomputed at construction; over-reports only for a space
   whose chunks interleave).
2. per destination chunk `c`: accumulators `num`, `cover` sized
   `length(cellindices(dst, c)) × nslices` — **per chunk, never per domain** —
   plus `total` and a `vals` output buffer of the chunk's length.
3. `connectedchunks!` into a reused `Int` vector, against the cached source
   chunk tree.
4. per connected source chunk `s`: `blockfor(plan, c, s)` → `addreference!` into
   `total` → `chunkranges(src, s, srcsize)` → **one** read into a buffer reused
   across the loop → `applyblock!` per slice through `_applyslices!`.
5. `finalize!` once per destination chunk per slice, then scatter the cells the
   request asked for.

**Resident at any moment**: one source chunk × the requested slices, one
`WeightBlock` in hand (plus whatever the storage bound keeps), the destination
chunk's four accumulators, and the output block. The source array is never
materialized. That is the floor T8's budget has to work under — the only thing
`budget` can add is holding *several* source chunks to load them in parallel.

Measured (toy 64×32, 512-cell destination chunk, 8 source chunks): 27.7 kB per
warm read, all of it the O(chunk) accumulators and the toy space's own
`cellindices` allocation; nothing per element. `_applyslices!` is the function
barrier that recovers the block's concrete type — its optimized IR and
`_writechunk!`'s have no `Any` values and no runtime dispatch.

`hasdenom` is taken as the **OR** over a destination chunk's blocks, not from
one: a chunk pair that shares no cells never calls `adddenom!` and so reports
`denom === nothing` even for a method that always denominates. An empty block
contributes zero either way, so the OR is the only reading that survives a
sparse chunk pair.

## New seam: `chunkranges`

    chunkranges(space, chunk, spatialsize::NTuple{NS,Int}) -> NTuple{NS,UnitRange}

The index ranges of a chunk in the **array's** spatial dims, in array dimension
order. Contract: `vec(A[chunkranges(...)...])` is the chunk's cells in
`cellindices` order. This is what turns a chunk number into one `readblock!`.

- Generic implementation recovers the rectangle from `cellindices` and *verifies*
  it element by element, throwing an `ArgumentError` naming this seam when a
  chunk is not a lattice rectangle.
- `chunkranges(::RasterGrid, chunk, ssz)` is defined here (in `lazy.jl`) from
  T2's `chunkbox`, honouring `xfast` — `(xr, yr)` for an `(X, Y)` array and
  `(yr, xr)` for a `(Y, X)` one. Tested both ways against the eager answer with
  real `Conservative` weights.
- **T9 should define it for the DGG spaces.** The generic path materializes the
  chunk's `cellindices` vector on every read; a space that knows its own
  rectangle should not.

## Seams for T8

- `budget` is carried and ignored. The obvious hook is step 4 above: batch the
  connected source chunks into groups fitting the budget and load a group in
  parallel, or keep the current one-at-a-time loop when they do not fit. Nothing
  else in `readblock!` has to change — the accumulators already sum over
  arbitrary block subsets in arbitrary order.
- `Spilled(dir)` still errors. The storage seam it must implement is exactly
  `getblock!(storage, key, build) -> CachedBlock` plus `nblocks` /
  `storagebytes`; `blockfor` and everything above it are storage-agnostic.
- The reference vector lives in `CachedBlock` beside the block, so a spilled
  format must round-trip `denom` (`nothing` is meaningful) or recompute the
  reference on reload.
- Chunking invariance (acceptance law 5) has a first form here — a second source
  chunking over the same field gives the same answer — but only for the toy
  diagonal method; T8 should raise it to a conservative regrid over two real
  raster chunkings.

## Seams for T9

- Destination chunks with **contiguous** `cellindices` (a DGGS `descendant_range`
  is one) make `eachchunk` report the destination's real chunks; a space whose
  chunks interleave silently degrades to one whole cell-axis chunk, which is
  correct but coarse.
- `chunkextents(space)` requires the chunk tree's leaf indices to be exactly
  `1:nchunks(space)` and throws naming the space if they are not.
- Output dims are still `(1:ndst, others...)`; the cell axis is the plain axis
  T5 left for DGG to replace.

## Deviations

1. `ChunkedPlan` gained a seventh field, `chunks`, over the docstring T1 froze —
   the design's "output chunking" had nowhere else to live.
2. `PerChunk` bounds on **both** entry count and bytes; the design named only a
   capacity.
3. `LazyRegridArray` caches the source's `chunktree` and the destination's chunk
   extents and spans at construction. All three are geometry, no data is read
   (L1 holds), but it is O(nchunks) memory and O(ncells) construction work for
   the spans.
4. A second `readblock!` of the same destination chunk re-reads the source. Only
   weights are cached, never data — L4 counts builds, and the read count is
   asserted to be the connected set again, not zero.

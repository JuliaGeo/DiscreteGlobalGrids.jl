## `budget` — one number, two consumers

`budget` is now the plan's whole transient-memory target and is split once, in
`plans.jl`:

    weightbudget(budget) = 25 % of it     # PerChunk maxbytes
    databudget(budget)   = the rest       # loaded source chunks

Fixed shares, not adaptive: an adaptive split makes residency depend on the
order chunks were touched in, which is the property a budget exists to remove.
Weights get the smaller share because an evicted block is rebuilt from geometry
while evicted data must be re-read.

- **L3's weight half (P1's failure).** `plan_regrid(...; lazy = true)` now
  defaults `storage` to `PerChunk(; maxbytes = weightbudget(budget))` instead of
  the unbounded `PerChunk()`. An explicit `storage =` still wins, so
  `PerChunk()` remains available and T7's tests, which pass it, are unaffected.
- **L3's data half — hold vs stream.** `readblock!` opens a `SourceHold` per
  call, bounded by `databudget`. Per destination tile it sums the bytes of the
  connected set (`connected chunks × requested non-spatial chunks`) and decides
  once: fits ⇒ every loaded chunk is kept and reused, including by later tiles
  of the same request; does not fit ⇒ nothing is kept and each chunk is loaded
  into the one reused scratch buffer, applied, and dropped.
- **Resident floor when streaming**: one source chunk + one `WeightBlock` + the
  tile's accumulators + the output block. Nothing survives the call — weights
  are cached across reads, data never is (T7 deviation 4 stands).
- Measured on the fan-in test (16 source chunks × 4 band tiles, 1 KiB per
  chunk): held peak **16384 B**, 16 loads / 32 hits; streamed peak **1024 B**,
  48 loads / 0 hits; **identical output**. Resident blocks 64 → 1.

Accounting hook: `residency(A) -> LazyStats` (loads, hits, skipped, dropped,
bytes, peakbytes). Updated per chunk load, never per element. This is what the
L3 assertions read instead of `Sys.maxrss()`.

## `Spilled(dir)`

`Spilled(dir; capacity, maxbytes)` — a `PerChunk` LRU in front, files behind,
both reached through the same `getblock!(storage, key, build)` seam, so nothing
above storage changed.

- **Keying**: each `Spilled` stamps a random 64-bit tag into every file name at
  construction (`gr-<tag>-<tile>-<srcchunk>.blk`). A second plan pointed at the
  same directory is therefore a **cold** cache, never a wrong one — a file says
  nothing about the spaces, method or chunking that produced it, so there is no
  key that could safely alias. Files are left behind; `dir` is the caller's
  scratch.
- **Format** (private, minimal, **not durable** — this package version, this
  machine): magic `"GRWB"`, version byte, `Int64` `(ndst, nsrc, nnz)`, `colptr`,
  `rowval`, `nzval`, then a flag byte and `denom` if there is one. `nothing`
  denom is a distinct flag, not a zero-length vector — the two finalize
  differently. Written to a per-writer temp name and `mv`d into place, so a
  racing reader never sees a half file. Dense-weight blocks are refused with a
  message naming `PerChunk`.
- The reference vector is **not** stored; it is recomputed on reload (one pass
  over the nonzeros) so it cannot disagree with the weights. This answers T7's
  "must round-trip `denom` or recompute the reference".
- Verified under 4 threads: 8 tasks reading one destination tile through
  `Spilled` agree with the eager answer.

## `missingval`

Kwarg on `regrid`/`regrid!`/`plan_regrid`, stored as the last field of both
`DirectPlan` and `ChunkedPlan` (added last, with outer constructors preserving
the old arities — T7's 7-positional `ChunkedPlan` call still compiles).

The validity predicate is now two-argument throughout:

    isvalidvalue(x, missingval) = !ismissing(x) && !isnan(x) && !isequal(x, missingval)

`isequal`, not `==`: it is total, so `missing` against a sentinel answers
`false` rather than `missing`. `missingval === nothing` is a `Nothing` branch
that compiles away, so a source without a sentinel pays nothing. `anyinvalid`
gained the same second argument and no longer takes the element-type shortcut
when a sentinel is declared — an `Int` raster with `-9999` for nodata does hold
invalid values.

Apply-time only; weights never see it. Verified bit-identical against the same
field with sentinels replaced by NaN, under both policies, eagerly and lazily.

## `knownempty` — and the one place it is *not* free

    knownempty(data, ndchunk::Tuple{Vararg{AbstractUnitRange}}) = false

Keyed on the **source array's own N-D chunk**, every dimension, in the array's
dimension order. `true` claims every element of that chunk is invalid — what a
missing Zarr chunk or an absent tile reads as. It is not a claim about zeros.

Two consumption points, exactly as the tasks doc specifies:

1. **Per (spatial chunk × non-spatial chunk)**, in the read loop. The requested
   slices are split along the source's own non-spatial chunk grid
   (`_slicegroups`), and each combination that answers `true` skips its load and
   its matvec. The pair's block is still built and its reference still
   accumulated, so this is bit-identical by construction. A request lying inside
   one source chunk is one group, so nothing else about how reads are issued
   changed.
2. **Whole pair, before any weight build**, when the chunk is empty at *every*
   non-spatial chunk (memoized per source chunk in `emptymemo`).

**Point 2 is gated, and this is the T8 decision worth reviewing.** A dropped
pair contributes no reference weight, and `Weighted(t > 0)` measures coverage
against exactly that reference — so dropping it is *not* semantics-preserving
for the default policy: a destination that load-and-mask would blank comes back
with a value. The drop is therefore taken only when
`usesreference(policy) == false`, i.e. `Extensive()` or `Weighted(0)`. Under
`Weighted(t > 0)` the block is built and its reference counted while every read
and matvec is still skipped — the IO saving is kept, the weight-build saving is
not.

`test_lazy.jl`'s "dropping is licensed, not assumed" is the mutant killer: a
destination whose stencil takes one valid cell from a live chunk and four from
an all-empty one is blanked under `Weighted(0.5)`, and comes back with a value
if the pair is dropped. Both policies are asserted equal to the oracle-less run.

## Destination chunking (P1's P8 blocker)

`readblock!`'s unit is now a **destination tile**, not necessarily a destination
space chunk (`DestTiling` in `lazy.jl`). Rules, in order:

1. `plan.chunks` given (`GridChunks` or a tuple of sizes, length checked against
   the output's dimensionality) ⇒ its cell axis defines the tiles.
2. else the destination space's chunks, if they partition the cell axis into
   **more than one** ascending contiguous run ⇒ tile `t` is chunk `t`, block key
   `(t, s)` unchanged, T7's behaviour exactly.
3. else a derived partition: `min(budget/8/40 cells, ceil(ndst / nchunks))` —
   budget-sized, but never coarser than the space's own chunk granularity, so a
   destination that reports one whole chunk still streams.

`eachchunk`'s cell axis is the tiling; `regrid!` drives that loop, so a
`chunks =` destination materializes tile by tile. A tile that is a run of cell
positions gets its `dinds` from the run and its blocks built over it — weight
work is proportional to the tile, not recomputed per tile. Discovery for such a
tile is the **union** of the descents against every destination chunk whose span
overlaps the run (`connectedchunks!(out, ::AbstractVector{<:SphericalCap}, tree)`
in `discovery.jl`); a union of descents, not a merge of caps, because merging
two distant caps can cover half the sphere.

## Acceptance law 5

`test_lazy.jl` "law 5 — chunking invariance": one field, one destination, real
`Conservative` weights, three source chunkings (8×4, 4×8, 16×8 — no shared
boundary), agreeing to `rtol = 1e-12` with each other and with the eager
whole-domain answer. Expected connectivity is computed **at runtime** from
`chunkextents` of both spaces (`t8_pairs`), so tightening a space's chunk caps
cannot silently invalidate it.

## P7 — the column walk (optional item, done)

`_accumulate!` now picks between two walks for a `SparseMatrixCSC`:
column-by-column as before, or nonzero-first with the owning column recovered by
`searchsortedlast` over `colptr`. Crossover measured, not guessed: the walk
costs ~0.33 ns/column, a column found by binary search ~78 ns, so the search
pays below roughly one nonzero column in 240 — `nnz * 256 < ncols`. Keying on
`nnz` over-estimates density, which errs toward the walk, the branch with no bad
case.

Measured at 500 000 columns: an **empty** block 165 µs → **0.9 µs** (183×), 100
nonzero columns 165 → 5.4 µs, 1000 → 80 µs; denser blocks are routed to the
unchanged walk. This is the cost a discovery superset pays per spurious pair, so
it compounds with P3's over-reporting rather than waiting on it.

## Laws

L1, L2, L4 unchanged and still asserted by T7's testsets, unmodified. L3 now
holds for both halves. L5 re-verified: `applyblock!` allocates **0** on the
plain and the sentinel path; a warm whole-array read allocates O(chunk +
held), nothing per element.

## Deviations

1. **`storage` kwarg added** to `regrid`/`regrid!`/`plan_regrid`. Not in the
   design's signature, but `Spilled` is unreachable from the documented API
   without it, and T10's acceptance requires spill through the API. The eager
   path rejects it rather than ignoring it.
2. **`knownempty`'s pair-level drop is policy-gated** (above). The tasks doc
   describes the drop unconditionally; it is not semantics-preserving for
   `Weighted(t > 0)`, and the brief's "every skip must be semantics-preserving"
   won.
3. `DirectPlan` and `ChunkedPlan` each gained a trailing `missingval` field.
   Old positional arities are preserved by outer constructors.
4. `ChunkedPlan`'s keyword constructor now defaults `storage = nothing`
   (meaning "derive from budget"), not `PerChunk()`.
5. `Spilled(dir)` no longer throws; `test_lazy.jl`'s "storage policies" testset
   lost that assertion (see the corrective line appended to T7.md).
6. `LazyRegridArray` gained a type parameter (`NO`, the non-spatial dimension
   count) and five fields: the tiling, the source's non-spatial chunk grid, the
   full grid of non-spatial chunk combinations, the emptiness memo, and stats.
   `dstspans` is gone — the tiling carries the runs.

## Seams for T9 / T10 / P2

- **`knownempty(data, ndchunk)`** is the hook a backend implements — Zarr chunk
  presence, absent tiles. It is keyed on `data`'s own `eachchunk` ranges, so an
  adapter needs no geometry. Note the policy gate before promising a caller that
  weights are skipped.
- **`missingval`** is the kwarg T9 wires from Rasters metadata
  (`Rasters.missingval(raster)` straight through; `nothing` when there is none).
- **`chunks`** is now load-bearing for a destination space with one chunk. A
  DGGS destination whose `descendant_range`s partition the cell axis gets rule 2
  and needs nothing. A `RasterGrid` destination built from a tiled array gets
  rule 3, whose tiles are runs of cell positions — full raster rows, which
  `_indexrect` still recognizes as a lattice rectangle.
- **`residency(A)`** is the accounting P2 should read for streaming residency;
  it is exact and free, unlike a `maxrss` delta.
- **P3 (whole-sphere chunk extents) is still open** and is now the largest lazy
  win: it is in `rastergrid.jl`/`conservative.jl`, which T8 does not own. The
  empty-block cost it produces is 183× cheaper, but the weight builds it causes
  are not.
- **Suggested exports** (module file frozen, none required — all reachable as
  `GlobalRegridding.x`): `knownempty` and `isvalidvalue` (backends extend the
  first, read the second), `residency`, `LazyStats`, `weightbudget`,
  `databudget`, `spilledfiles`, `usesreference`.
